# 本地优先的屏幕内容与观点采集助手

这是一个面向 Windows + Chromium 的本地演示项目。它允许用户主动冻结当前画面、框选内容、优先读取浏览器原文并在必要时执行离线 OCR，随后生成带截图、来源、时间码、置信度和个人态度的观点卡片。

所有数据默认只保存在本机。程序不会因为用户点击、点赞或停留就替用户判断立场；新卡片的默认态度始终是“未知”。

## 当前状态

当前已经完成 **T0–T8 的代码闭环**，并加入首版半自动观察模式：除主动采集、识别、审核与保存外，现在还包括有界内存候选收件箱、本地观点库、桌面搜索与筛选、编辑和彻底删除、JSON/Markdown 导出，以及只监听回环地址的只读 HTTP 检索服务。

用户已在真实 Chrome 中报告 T7 的 12 项验收全部通过：扩展加载、URL/标题、选中文字、静态 OCR、截图保存、丢弃不落盘、暂停和播放中的视频时间码、密码输入、验证码输入、银行卡输入及同源 iframe 密码输入暂停。多显示器和高 DPI 仍是独立的人工验收项，不能由这次结果代替。

当前仓库已经具备：

- Python 包与固定目录骨架；
- 集中的快捷键、数据库、截图目录和端口配置；
- 使用 Pydantic 定义的观点卡片模型；
- Windows 本机开发环境安装和启动说明。
- 鼠标所在显示器的 `mss` 抓帧、PNG 保存和捕获元数据；
- PySide6 冻结画面浮层、拖动框选、Enter 确认及 Esc/右键取消；
- 浮层逻辑坐标到原图物理像素的 DPI 无关映射；
- T1/T2 自动测试与真实桌面人工验收脚本；
- RapidOCR 单例懒加载、不同引擎结果格式规范化、阅读顺序合并和长度加权置信度；
- SQLite 卡片增删改查、FTS5 全文检索、字段白名单更新与截图路径边界删除。
- 仅监听 `127.0.0.1` 的 WebSocket 桥，以及超时后不阻塞采集的安全降级；
- 只在桌面端主动请求时返回活动标签 URL、标题、选中文字和视频时间码的 Chrome 扩展。
- DOM 选中文字优先、选区 OCR 降级、两类截图与 SQLite 记录一致提交的卡片生成流水线。
- 使用 Windows 原生 `RegisterHotKey` 的 `Ctrl+Shift+S` 全局快捷键，不安装键盘监听钩子；
- 系统托盘、后台 OCR、后台安全保存和随应用启动/停止的浏览器桥；
- 分开保留只读提取原文和可编辑整理文字、查看选区与完整画面、选择五种态度并填写备注的审核窗口；
- 密码管理器、密码/验证码/支付输入框的捕获暂停，以及捕获前后页面和窗口一致性检查；
- 审核前的候选文字与两张画面只保留在内存；点击保存后才进入受控落盘流程。
- 可按关键词、态度和文字来源筛选的本地观点库，可查看两类截图、来源和原始证据；
- 在不覆盖初始原文的前提下编辑整理文字、态度和备注，并可连同全文索引与证据截图彻底删除卡片；
- 将当前桌面搜索和筛选结果导出为 JSON 或 Markdown；
- 随桌面端启动的 `127.0.0.1:8000` 只读检索网页和 HTTP 接口，不提供新增、修改、删除或执行型路由；
- Chrome 扩展 0.3.0 的有限退避、离线提示、工具栏点击重连，以及选中文字和已启用 HTML5 字幕轨道的结构化观察信号；
- 用户明确开始、绑定当前 Chrome 标签页和固定证据区域的半自动观察；候选最多 20 条或约 192 MiB，只在内存等待人工审核。

当前主入口既可完成“快捷键 → 冻结 → 框选 → 本地识别 → 人工审核 → 保存/丢弃”，也可完成“开始半自动观察 → 框定证据区域 → 稳定文字进入内存收件箱 → 逐条审核”。托盘中的“打开观点库”进入可编辑资料库，“打开只读检索网页”进入供本地助手读取的回环网页。

## 核心原则

- 本地优先：默认不上传屏幕、文字、截图或观点卡片。
- 用户主动：主动捕获和半自动观察都由用户明确触发；观察只在绑定的 Chrome 窗口位于前台时抓帧，不做后台永久录屏。
- 不替用户表态：`unknown` 是默认立场，操作行为不等于认同。
- 证据可追溯：保留原文、截图、来源和时间码，处理结果不覆盖原始证据。
- 诚实降级：优先使用 DOM 等结构化原文，取不到时才使用 OCR；不确定就标记未知。
- 只读接入：面向本地助手的接口只提供检索和导出，不提供执行能力。

## Windows 本机运行

### 1. 前置条件

- Windows 10 或 Windows 11；
- Python 3.11，安装时建议勾选“Add Python to PATH”；
- Git（仅开发和同步仓库时需要）。

### 2. 首次初始化开发环境

开发依赖必须安装在仓库 D 盘的 `.venv` 中；pip 缓存、安装构建临时文件和测试临时文件也放在仓库内，不占用系统盘的默认缓存目录。

新开 PowerShell 后，复制并执行下面整段命令：

```powershell
Set-Location "D:\codex projects\capture_assistant"
$projectRoot = (Get-Location).Path
$venvPath = Join-Path $projectRoot ".venv"
$pythonExe = Join-Path $venvPath "Scripts\python.exe"
$pipCachePath = Join-Path $projectRoot ".cache\pip"
$tempPath = Join-Path $projectRoot ".cache\tmp"

New-Item -ItemType Directory -Force -Path $pipCachePath, $tempPath | Out-Null
$env:PIP_CACHE_DIR = $pipCachePath
$env:TMPDIR = $tempPath
$env:TEMP = $tempPath
$env:TMP = $tempPath

py -3.11 -m venv $venvPath
& $pythonExe -m pip install --upgrade pip
& $pythonExe -m pip install -r (Join-Path $projectRoot "requirements-dev.txt")
```

`requirements-dev.txt` 会同时安装运行依赖和测试依赖。所有包都会进入 `D:\codex projects\capture_assistant\.venv`，pip 缓存进入 `.cache\pip`，临时文件进入 `.cache\tmp`。

这些 `$env:` 设置只影响当前 PowerShell 进程及其启动的子进程，不会修改 Windows 的系统级或用户级环境变量。关闭窗口后设置自动失效；本项目不要求也不建议使用 `setx`。

### 3. 每次打开新的 PowerShell

新的 PowerShell 不会继承上一次会话的缓存路径。开始开发、安装依赖或运行测试前，复制下面整段命令恢复当前会话配置：

```powershell
Set-Location "D:\codex projects\capture_assistant"
$projectRoot = (Get-Location).Path
$pythonExe = Join-Path $projectRoot ".venv\Scripts\python.exe"
$pipCachePath = Join-Path $projectRoot ".cache\pip"
$tempPath = Join-Path $projectRoot ".cache\tmp"
New-Item -ItemType Directory -Force -Path $pipCachePath, $tempPath | Out-Null
$env:PIP_CACHE_DIR = $pipCachePath
$env:TMPDIR = $tempPath
$env:TEMP = $tempPath
$env:TMP = $tempPath
```

无需激活虚拟环境；后续命令显式使用 `$pythonExe`，可以避免误用系统 Python。

RapidOCR 首次初始化可能比普通模块导入慢；OCR 模型必须保持离线使用，不应把识别内容发送到网络服务。

### 4. 验证数据模型

```powershell
& $pythonExe -c "from app.models import Card; print(Card.schema())"
```

命令应输出 `Card` 的 JSON Schema。若当前 Pydantic 版本显示兼容性弃用提示，但仍能输出 Schema，不影响 T0 验收；后续可同时提供新版 `model_json_schema()` 调用。

### 5. 启动程序

```powershell
& $pythonExe -m app.main
```

启动后程序常驻 Windows 右下角系统托盘，但不会自行开始观察或采集。只有用户从托盘明确点击“开始半自动观察”后，程序才会在绑定的 Chrome 窗口位于前台时检查结构化文字并按需抓取证据；停止观察、切到其他应用或退出后不会继续抓屏。浏览器桥、只读检索服务和全局快捷键会随程序一起启动。

第一次使用按以下顺序操作：

1. 在 `chrome://extensions` 中确认“本地屏幕内容与观点采集助手”版本为 0.3.0 并已启用；从旧版升级后必须点击一次“重新加载”，再刷新准备测试的普通网页；
2. 打开普通网页或视频。若希望保留网页原文，可以先用鼠标选中文字；不选也可以，之后会对框选区域离线 OCR；
3. 让目标页面保持在前台，把鼠标放到要捕获的显示器上，按 `Ctrl+Shift+S`；
4. 在冻结画面上拖动框选，按 Enter 确认，或按 Esc/右键取消；
5. 等待本机识别完成，在审核窗口核对选区截图和完整冻结画面；识别原文保持只读，可另行校对“整理文字”，再选择“暂不判断、认同、反对、存疑、只是有用”并填写备注；
6. 点击“保存卡片”后，按钮会显示“正在保存”，程序在后台写入数据库和两张截图并成为正式资料；保存期间不能关闭审核窗。点击“丢弃”、按 Esc 或关闭尚未保存的审核窗，只释放内存候选，不会留下数据库记录或图片文件。

保存后的数据库位于 `D:\codex projects\capture_assistant\data\capture_assistant.sqlite3`，截图位于 `D:\codex projects\capture_assistant\data\screenshots`。程序会按卡片组织这些内容；可从托盘打开观点库查看和整理，不需要手工修改数据库或移动截图。

如果托盘菜单提示快捷键被占用，先关闭占用 `Ctrl+Shift+S` 的程序，再重新启动本应用。托盘菜单中的“退出”会安全停止快捷键、浏览器桥和只读检索服务；正在识别、审核、保存或导出时会先阻止退出，避免留下未确认内容。

### 7. 人工验收截图与框选

先把鼠标移到需要测试的显示器，再运行截图脚本：

```powershell
& $pythonExe -m tests.manual_capture --save-full-screen
```

脚本默认等待 3 秒，方便把鼠标移到需要测试的显示器；随后在仓库根目录生成 `test_capture.png`，并打印图像尺寸、DPI 缩放比例和前台进程名。`--save-full-screen` 表示你明确同意把可能含敏感信息的整屏画面保存为本地测试文件。

随后运行冻结框选脚本：

```powershell
& $pythonExe -m tests.manual_overlay
```

在冻结画面上拖动鼠标框选，按 Enter 确认，或按 Esc/右键取消。确认后会生成 `test_crop.png`；检查裁剪结果是否与亮色框选区域一致。两个测试文件均被 Git 忽略，只保存在本机，验收后可以删除。

### 8. 人工验收 Chrome 扩展与本机桥

扩展需要 Chrome 116 或更高版本。先在项目 PowerShell 中启动只用于人工验收的本机桥：

```powershell
& $pythonExe -m tests.manual_bridge
```

然后在 Chrome 中完成以下步骤：

1. 打开 `chrome://extensions`；
2. 打开右上角“开发者模式”；
3. 首次安装时点击“加载已解压的扩展程序”并选择 `D:\codex projects\capture_assistant\extension`；已经安装过时，找到该扩展并点击“重新加载”；
4. 打开一个普通 `http://` 或 `https://` 页面，选中一段文字；若页面含视频，可先播放到任意时间；
5. 回到 PowerShell 按回车，然后在 5 秒内立即切回刚才的 Chrome 页面，并让 Chrome 保持在前台；
6. 等待读取完成后再回到 PowerShell，检查 URL、标题、选中文字和视频时间码是否正确。

扩展不申请 `tabs`、Cookie、网络拦截或文件访问权限，但为了在用户从桌面端主动采集时读取当前网页，它需要把只读内容脚本注入普通 HTTP/HTTPS 页面。扩展只连接 `ws://127.0.0.1:8765`，只在桌面端发出 `get_context` 请求时读取页面内容；普通网页 Origin 会被本机桥拒绝。

扩展 0.3.0 在桌面端未运行时只进行有限次数的快速重试，随后停止后台探测，避免持续刷错；把鼠标停在扩展图标上可以看到连接状态。启动桌面端后，点击一次 Chrome 工具栏中的扩展图标即可立即重连；也可以在 `chrome://extensions` 中点击“重新加载”。Chrome 设置页、扩展页和其他受限页面不能注入内容脚本，此时返回 `None` 并降级到 OCR 属于正常行为。

开发者模式会记录底层 WebSocket 首次握手失败：若 Chrome 启动时桌面端尚未监听 `127.0.0.1:8765`，“错误”页可能保留一条历史 `ERR_CONNECTION_REFUSED`。JavaScript 无法在保留自动连接能力的同时抹去 Chrome 已记录的这次握手；这不表示扩展之后仍不能工作。先启动桌面端，再重新加载扩展或点击扩展图标即可恢复连接；确认采集正常后可在扩展错误页清除这条历史记录。

当前演示版的扩展与桌面桥固定使用回环端口和协议版本，但尚未做强配对认证，因此安全边界是假设同一 Windows 账户下运行的其他本机进程可信。不要在运行来历不明的本机程序时采集敏感页面；高熵配对凭据和更强的本机进程隔离应在后续安全阶段单独实现。

人工脚本会把当前上下文直接显示在终端中，不写入日志或数据库。不要在含访问令牌的 URL、密码框或其他敏感页面上做人工测试。扩展会拒绝读取常见密码、验证码和银行卡输入字段；T7 主程序会在截图前后各检查一次，检测到时立即释放内存画面并停止。

视频验收时先让普通 HTML5 视频播放到一个明显时间点，再重复测试。输出中的 `video_time` 应接近当时秒数；硬字幕本身仍由框选后的 OCR 获取。某些 Canvas 播放器、DRM 视频或站点自定义播放器拿不到时间码，此时保留 `None` 或降级到 OCR 属于预期边界，不会尝试绕过保护。

### 9. 人工验收完整 T7 流程

仓库附带一个完全本机运行的验收页，可测试普通文字、自动生成的短视频，以及密码/验证码/银行卡和同源 iframe 密码框的捕获暂停。另开一个 PowerShell，恢复第 3 节的 `$pythonExe` 后运行：

```powershell
& $pythonExe -m http.server 8877 --bind 127.0.0.1 --directory (Join-Path $projectRoot "assets")
```

在 Chrome 打开 `http://127.0.0.1:8877/manual_test.html`。测试顺序如下：

1. 先等待页面中的本机视频生成并循环播放；
2. 启动主程序 `& $pythonExe -m app.main`，确认托盘出现；不要同时运行 `tests.manual_bridge`，否则两者会争用 8765 端口；
3. 验证普通选中文字后捕获、未选中文字时 OCR、视频时间码、态度与备注保存；
4. 分别只点击四个敏感测试输入框（包括 iframe 内的测试密码框），不输入任何真实内容，再按快捷键；程序应暂停且不出现框选层；
5. 创建一张候选后点“丢弃”，再创建一张、把文字改掉并标记“存疑”后保存；
6. 从托盘退出。正在识别或审核时，退出应被阻止。

如果只想单独确认全局快捷键是否能跨应用触发，可以先退出主程序，再运行：

```powershell
& $pythonExe -m tests.manual_hotkey
```

真实双显示器验收还应加一项：让 Chrome 位于屏幕 1、鼠标位于屏幕 2 后触发捕获。程序可以让你 OCR 屏幕 2 的主动框选，但不能把屏幕 1 的 DOM 原文错误关联过来。

本轮用户已报告上述采集闭环中的 12 项全部通过，包括暂停/播放视频时间码及四类敏感输入暂停。这一结果不包含真实双显示器或高 DPI 验收，因此这两项仍需按各自章节单独测试。

### 10. 人工验收半自动观察模式

半自动观察不是开机自启功能。每次会话都需要用户在目标 Chrome 标签页位于前台时，从托盘明确点击“开始半自动观察……”，并在冻结画面上框出要保留的证据区域。首版只自动接收两类结构化文字：用户保留选中的普通网页文字，以及播放器已经启用的 HTML5 `captions`/`subtitles` 字幕轨道；硬字幕、Canvas 字幕和任意页面像素变化尚不会自动 OCR。

先按第 9 节启动 `assets/manual_test.html` 和桌面主程序，在 `chrome://extensions` 重新加载 0.3.0 扩展，**再刷新已经打开的本机验收页**。扩展重新加载不会替旧标签页自动注入新版内容脚本；少了刷新可能出现 `content_script_unavailable`。然后按以下顺序验收：

1. 等本机测试视频显示“本机测试视频和三条原生字幕已生成”，让该 Chrome 标签页保持前台；
2. 右击系统托盘图标，选择“开始半自动观察……”，在冻结画面中只框住视频区域并确认；
3. 切回原 Chrome 标签页并让视频播放。相同文字需要连续稳定出现两次才会形成候选，三条测试字幕应逐步进入“候选收件箱”；
4. 打开候选收件箱，确认列表明确显示“尚未保存”，逐条点“审核此条”；在正式审核窗中选择态度后保存，或直接丢弃；
5. 保存的候选应出现在观点库并带有来源、时间码、选区截图和完整证据画面；丢弃的候选不应产生数据库记录或 PNG；
6. 重新开始一次观察并切换到另一个 Chrome 标签页，程序应安全暂停；切回验收页后需重新开始一轮观察，再分别让密码、验证码和银行卡测试输入框获得焦点，每一种都应独立触发暂停；
7. 先向下滚动，让测试视频完全离开浏览器可视区域；选中“普通文字”中的一句并保持选中，再开始观察并框住该段落。切回原标签页后，选中文字应只进入一次收件箱。唯一可见视频的活动字幕优先于普通选区，因此不要在视频仍可见且字幕正在显示时做这一项；
8. 点击“停止半自动观察”。停止只终止继续发现，已在收件箱中的候选仍留在内存，直到审核、丢弃或退出程序。

固定安全边界如下：

- 只绑定开始时的 Chrome 窗口和标签页；用户切到其他应用时只等待，不在后台抓屏；
- 只有浏览器视口中恰好一个视频可见时才读取该视频的字幕和时间码；多视频同时可见时不猜测目标，请滚动到只保留目标视频可见后重新开始；
- 扩展失联、标签页变化、敏感输入、显示器布局/设备身份变化或本地处理错误都会停止会话，不自动降级为持续 OCR；
- 候选最多 20 条且总估算内存不超过约 192 MiB，达到上限时释放最旧的未审核候选；
- 每个候选的文字、选区图和完整证据画面在审核前都只存在于当前进程内存；只有点击正式审核窗中的“保存卡片”才会写入数据库和截图目录；
- 收集、停留、重复出现和保存均不代表认同，候选态度始终从 `unknown` 开始；
- 退出程序会明确提示未审核候选将从内存丢失。已保存卡片不受影响。

### 11. 使用本地观点库与只读接口

保持主程序运行，在 Windows 托盘图标上点击右键：

- 选择“打开观点库”：进入桌面资料库。左侧可按关键词搜索，并按态度、文字来源（网页原文或 OCR）筛选；右侧可核对选区截图、完整画面、来源、视频时间和初始提取原文。
- “初始提取原文”始终只读；只能在“整理文字”中校对，并可修改态度与备注。修改后必须点击“保存修改”。
- 点击“彻底删除”会再次确认；确认后会同时删除卡片、全文索引、选区截图和完整截图，无法撤销。
- “导出 JSON”或“导出 Markdown”只导出左侧当前搜索和筛选结果，最多显示并导出前 200 条。存在未保存编辑时会要求先保存或放弃。默认目录是 `D:\codex projects\capture_assistant\data\exports`；若手动选择其他位置，建议仍使用 D 盘本地目录，不要选择网络路径。
- 选择“打开只读检索网页”：用默认浏览器打开 `http://127.0.0.1:8000/`。这个网页可输入关键词、查看原文、态度、来源和截图，但不能修改资料。

可供本地个人助手读取的 HTTP 路由如下，全部只有 GET：

| 路由 | 用途 |
| --- | --- |
| `/` | 本机 HTML 搜索页；参数 `q`，可选 `limit=1..100` |
| `/search?q=关键词&limit=50` | 返回 JSON 搜索结果，`limit` 范围为 1–100 |
| `/cards/{卡片UUID}` | 返回单张卡片的 JSON |
| `/screenshot/{卡片UUID}?kind=selected` | 返回选区 PNG；`kind=full` 返回完整冻结画面 |
| `/export?format=json` | 下载全部卡片的 JSON；无关键词时单次上限 2000 张 |
| `/export?format=md&q=关键词` | 下载命中关键词的 Markdown；关键词导出上限 500 张 |

例如，在桌面端运行时可直接在浏览器中打开：

```text
http://127.0.0.1:8000/search?q=视频&limit=20
http://127.0.0.1:8000/export?format=md&q=视频
```

只读服务有以下固定边界：

- 只监听 `127.0.0.1:8000`，不接受局域网访问，也不要把它改成 `0.0.0.0`；
- 不提供 POST、PUT、PATCH、DELETE、OpenAPI 文档或任何执行型工具；
- 只接受本机 Host/Origin，响应禁用缓存和嵌入；截图只从受控截图目录读取，并验证 PNG、普通文件和大小上限；
- 网页、OCR 和卡片文字一律作为不可信资料返回，接入本地模型时必须放在数据区，不能拼接进系统指令。

人工验收 T8 时建议依次完成：

1. 先用 T7 流程保存两张关键词、态度或文字来源不同的卡片；
2. 从托盘打开观点库，验证关键词、态度和来源筛选；
3. 修改整理文字、态度与备注并保存，再关闭重开确认修改仍在；
4. 分别导出 JSON 和 Markdown，并确认文件位于选定的 D 盘目录；
5. 从托盘打开只读检索网页，验证搜索、单卡片和两类截图；
6. 用一张测试卡片验证“彻底删除”；不要拿重要资料测试，删除无法恢复。

### 12. 当前卡片生成流水线

`app.pipeline.build_card_from_selection()` 已经把一次确认后的冻结画面、像素选区和捕获元数据串成观点卡片：

- 捕获时前台是受支持的 Chromium 浏览器，并且扩展确认自己的浏览器窗口此刻获得系统焦点时，非空 DOM 选中文字优先，置信度记为 `0.99`；
- DOM 不可用、为空或桥在 0.3 秒内没有响应时，只对框选区域执行离线 OCR；
- 使用同一 UUID 保存选区截图和完整冻结截图，数据库只记录数据目录内的相对路径；
- 卡片始终以 `stance="unknown"` 创建，不把选择、点击或保存自动解释为认同；
- 空选区、空 OCR、路径越界、截图失败或数据库失败都会中止，本次新建截图会清理，已有同 ID 卡片和旧证据不会被覆盖或误删。

T7 的识别线程只在内存中完成裁剪、DOM/OCR、缩略预览和候选构造，GUI 主线程只负责框选与审核交互。点击保存后，独立保存线程才短暂建立内部草稿、写入截图并原子转为正式卡片；失败时审核窗保持打开并允许重试，若进程在保存阶段异常中断，下次启动会清理遗留草稿。

## OCR 与中文检索说明

- RapidOCR 只在第一次实际识别时加载，模块导入不会启动推理或访问网络。
- OCR 在本次内存处理阶段返回文字框、原文和分数；当前卡片只持久化合并原文、总体置信度和截图证据，尚不逐框保存坐标。低置信度内容不会被静默删掉。
- SQLite 优先使用 FTS5 `trigram`，适合三个及以上中文字符的子串检索；一到两个中文字符自动使用参数化子串查询。
- 若某台机器的 SQLite 不支持 `trigram`，程序会降级为 `unicode61`，中文查询继续使用子串兜底，但大型资料库的检索速度会较慢。
- 搜索只读取本地数据，搜索词作为数据处理，不会被当成 SQL、FTS 指令或助手指令执行。

## 已知边界

- 当前目标是 Windows + Chromium 演示版，不承诺跨平台能力一致。
- Canvas、自绘界面、受保护窗口和 DRM 内容可能无法获取结构化文字或截图。
- 敏感检测只覆盖已知密码管理器、常见语义输入框、开放 Shadow DOM、可访问的同源 iframe，以及保守拦截无法检查的聚焦跨域 iframe；关闭的 Shadow DOM、自绘控件或错误标注的输入框仍可能无法识别。扩展失联时程序会明确警告，但用户仍应在任何敏感页面取消捕获。
- OCR 与点击目标识别都可能出错，结果必须保留置信度并允许用户修改。
- 本项目不把网页或屏幕中的文字当成可信指令，也不会据此自动执行文件、网络或账户操作。
