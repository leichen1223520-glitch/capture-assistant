# T0–T9、半自动观察 O1 与 Obsidian 归档 O2 开发路线图

本路线图面向 Windows + Chromium 演示版。开发原则是先验证“用户主动框选 → 生成观点卡片 → 明确态度 → 本地找回”的最小闭环，再逐步加入动态视频和本地助手能力。

## 总体顺序

```text
T0 →（T3 与 T4 可并行）→ T1 → T2 → T5 → T6 → T7 → T8 →（O1、O2）→ T9
```

T3、T4 主要是纯逻辑模块，适合自动测试。T1、T2、T7 依赖真实 Windows 桌面、显示器和输入事件，除了代码检查外还必须由用户人工验收。

## T0：项目初始化与数据模型

### 目标

建立固定目录骨架，集中配置运行参数，并冻结所有后续模块依赖的观点卡片模型。

### 实现范围

- 创建 `app/`、`extension/`、`tests/`、`assets/` 和 `docs/`。
- 创建桌面端模块空壳，所有模块可以安全地独立 import。
- 在 `requirements.txt` 中声明 PySide6、mss、RapidOCR、FastAPI、uvicorn、websockets、Pydantic、Pillow 和 NumPy。
- 使用 Pydantic 定义 `Card`：原文、来源类型、置信度、两类截图路径、来源 URL/标题、视频时间码、应用名、显示器信息、创建时间、态度和备注。
- 在 `app/config.py` 中集中设置 `HOTKEY="ctrl+shift+s"`、数据库路径、截图目录、`WS_PORT=8765` 和 `API_PORT=8000`。
- 启动时创建本地数据目录，但不创建或提交真实用户数据。

### 验收

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -c "from app.models import Card; print(Card.schema())"
```

两条命令均应成功，且 Schema 中字段、默认值和约束与约定一致。

## T1：截屏抓帧模块

### 目标

捕获鼠标当前所在显示器，并记录后续进行坐标还原所需的环境元数据。

### 实现范围

- `grab_active_monitor() -> (PIL.Image, meta)`。
- 使用 mss 选择鼠标所在显示器，兼容多显示器布局。
- 通过 Windows API 获取 DPI 缩放；无法获取时降级为 `1.0` 并保留 TODO。
- 通过纯 `ctypes` 优先取得前台窗口进程名。
- `save_image(img, path)` 以 PNG 保存。
- 提供 `tests/manual_capture.py`。

### 验收

在真实 Windows 桌面运行人工脚本，生成 `test_capture.png` 并打印 `width`、`height`、`scale`、`app_name`。图片必须对应鼠标所在显示器。无桌面环境失败不算功能缺陷，但错误信息必须清晰。

## T2：冻结画面与框选浮层

### 目标

让用户在冻结的原始帧上主动框选内容，并准确返回原图像素坐标。

### 实现范围

- `select_region(frozen_image) -> QRect | None`。
- 全屏、无边框、置顶浮层，冻结帧作为背景。
- 周围半透明变暗、选区保持高亮。
- 拖动框选，Enter 确认，Esc 取消。
- 显示“拖动框选内容 · Enter 确认 · Esc 取消”和明显的“● 捕获中”状态。
- 正确处理高 DPI、缩放和多显示器坐标。
- 提供 `tests/manual_overlay.py`。

### 验收

人工框选后生成 `test_crop.png`；普通屏和高分屏上，保存区域都必须与用户所见选框一致。取消时不得留下卡片或截图。

## T3：离线 OCR 与行合并

### 目标

将框选图像转换为可追踪文字、总体置信度和原始文字框。

### 实现范围

- `ocr_image(img) -> (text, confidence, boxes)`。
- RapidOCR 模型采用进程内单例懒加载，import 时不加载模型。
- 根据文字框 y 坐标聚行、行内按 x 排序，再合并自然段。
- 总置信度按文字长度加权，不隐藏低置信度块。
- `boxes` 保留坐标、原文和分数。
- 提供中文和英文样例及自动测试。

### 验收

`tests/test_ocr.py` 能从两张固定样例中识别关键字，总体置信度大于 `0.5`。测试不得依赖网络或用户真实截图。

## T4：SQLite 存储与全文检索

### 目标

可靠保存、更新、检索和彻底删除观点卡片。

### 实现范围

- `Store.init_db()` 创建 `cards` 和 `cards_fts`。
- 使用触发器保持普通表与 FTS5 索引同步。
- 实现 `add_card`、`get_card`、`update_card`、`delete_card`、`search`、`list_recent`。
- 更新字段必须经过白名单和模型校验。
- 删除卡片时一并删除选区截图、整帧截图和 FTS 记录。
- 明确记录 `unicode61` 或 `trigram` 对中文检索的限制。

### 验收

使用临时目录和临时数据库插入三张卡片，完成关键词检索、态度更新和删除。删除后全文搜索不再命中，两个截图文件均不存在。

## T5：Chrome 扩展与 WebSocket 桥

### 目标

从浏览器取得比 OCR 更可靠的结构化上下文。

### 实现范围

- Manifest V3 内容脚本使用最小权限注入页面。
- 扩展仅连接 `ws://127.0.0.1:8765`，断线后有限退避重连。
- 0.3.0 版在桌面端离线时通过扩展图标提示等待状态，限制快速重试次数，并允许用户点击图标立即重连；开发者模式仍可能保留首次 WebSocket 握手失败的历史错误记录。
- 收到 `get_context` 后返回当前 URL、标题和选中文字；只有视口中恰好一个视频可见时才返回它的 `currentTime`，多视频来源不唯一时不猜测。
- 桌面端 WebSocket 服务只监听回环地址并维护当前扩展连接。
- `get_browser_context(timeout=0.3)` 超时或非浏览器场景返回 `None`，不得阻塞采集。
- 扩展只在其浏览器窗口此刻确实获得系统焦点时返回上下文；后台配置或其他 Chromium 实例必须降级，避免来源错配。
- README 补充在 `chrome://extensions` 加载/重新加载扩展、查看离线提示和点击重连的步骤。

### 验收

安装扩展，在有视频的网页选中一段文字，运行 `tests/manual_bridge.py` 能打印正确的 URL、标题、选中文字和视频时间。关闭浏览器时调用应在超时后安全降级。

用户已在真实 Chrome 中确认 URL、标题、选中文字，以及暂停和播放中的普通 HTML5 视频时间码均可读取。若桌面桥尚未启动，Chrome 开发者模式可能留下 `ERR_CONNECTION_REFUSED` 历史记录；先启动桌面端，再重新加载扩展或点击扩展图标即可恢复，不能把历史记录本身误判为持续故障。

## T6：文字降级链与卡片生成

### 目标

把框选、浏览器上下文、OCR、截图和存储串成可测试的单次流水线。

### 实现范围

- 新增 `build_card_from_selection(frozen_img, meta, rect) -> Card`。
- 有非空浏览器 selection 时，使用 DOM 原文，`text_source="dom"`、`confidence=0.99`。
- 没有选中文字时，仅对框选区域执行 OCR。
- 使用同一个 UUID 保存 `{id}.png` 与 `full_{id}.png`。
- 写入来源、视频时间、应用名、显示器信息和带时区创建时间。
- 立场始终默认为 `unknown`，随后写入数据库。
- 数据库和截图目录必须位于同一个受控数据根目录；冲突或任一步失败不得覆盖、误删既有证据。

### 验收

通过 mock 分别覆盖 DOM 和 OCR 两条分支；检查字段、相对截图路径、实际文件和数据库记录一致。浏览器桥超时不能导致 OCR 分支失败。

## T7：主程序与卡片确认界面

### 目标

跑通用户可见的最小产品闭环，并让用户亲自确认文字与态度。

### 实现范围

- 注册全局快捷键，加入系统托盘及“打开观点库、打开只读检索网页、退出”菜单。
- 后台线程运行 WebSocket 桥，服务生命周期随应用关闭。
- 快捷键严格执行：先读取浏览器敏感信号，再抓帧并复查，然后显示框选浮层、生成候选卡片，最后打开确认窗。
- 在截屏前检测浏览器密码/验证码等敏感输入信号；检测到时暂停，而不是继续降级 OCR。
- 比较捕获前后的前台窗口句柄、网页身份和目标显示器；发生切换或错配时禁用 DOM 元数据，只允许用户对实际框选区域 OCR。
- 确认窗同时显示只读提取原文和可编辑整理文字，并显示截图、来源、标题和时间码；人工整理不得覆盖原始证据。
- 提供认同、反对、存疑、只是有用四个明确按钮；未选择时保持未知。
- 提供备注、保存和丢弃；审核前候选只存在于内存，丢弃、Esc 或关闭窗口不得创建数据库记录或截图。
- 识别线程提前生成小尺寸审核预览；数据库与两张 PNG 的提交由独立保存线程完成，保存期间窗口保持锁定，避免 GUI 被整屏压缩或 SQLite I/O 阻塞。
- 使用 Windows `RegisterHotKey` 注册指定组合键，不安装全键盘钩子，也不增加第三方键盘监听依赖。
- 用户点击保存后才短暂建立内部草稿、写入两张截图并原子转为正式卡片；草稿不进入 FTS、最近列表或本地助手结果，异常中断的保存由下次启动清理。

### 验收

在 Windows 本机按快捷键完成一次框选，将卡片标记为“存疑”并保存；数据库中应同时保留只读提取原文、可选整理文字、态度和备注。Esc 或“丢弃”流程不得留下数据。还需验证：密码/验证码输入框停止捕获、双显示器 DOM 不错配、慢 OCR 时不能直接退出，以及重新启动会清理保存阶段异常中断的短暂草稿。

本轮用户报告 12 项真实 Chrome 验收全部通过：扩展加载、URL/标题、选中文字、静态 OCR、截图保存、丢弃不落盘、暂停视频时间、播放中视频时间、密码输入、验证码输入、银行卡输入、同源 iframe 密码输入暂停。该清单未包含真实双显示器和高 DPI，因此不能将这两项标记为已人工通过。

## T8：本机只读检索服务与搜索界面

### 目标

让本机用户通过桌面观点库整理资料，同时让本地个人助手只能检索、引用和导出，不能获得写权限。

### 实现范围

- 主程序随应用启动和停止 FastAPI，只允许监听 `127.0.0.1:8000`；端口占用或服务启动失败时明确中止启动。
- 托盘“打开观点库”进入桌面窗口；关键词可搜索原文、整理文字、来源标题和备注，并可按态度、`dom`/`ocr` 文字来源筛选，单次最多显示 200 张。
- 桌面窗口展示选区/完整截图、来源、视频时间、置信度和只读初始原文；本机用户可以单独编辑整理文字、态度和备注，不覆盖证据原文。
- 桌面端的“彻底删除”需要二次确认，并级联清理卡片、FTS 索引和两类证据截图。
- 桌面端把当前筛选结果原子导出为 JSON 或 Markdown，存在未保存编辑时阻止导出；默认使用 D 盘数据目录下的 `data/exports`，拒绝网络路径和覆盖数据库/截图。
- 托盘“打开只读检索网页”打开 `GET /`；页面只展示本机搜索表单、原文、来源、态度和安全截图链接。
- 对外提供 `GET /search`、`GET /cards/{id}`、`GET /screenshot/{id}?kind=selected|full` 和 `GET /export?format=json|md&q=...`。
- API 的搜索列表上限为 100；带关键词导出上限为 500；无关键词导出使用单查询快照，超过 2000 张返回 413，避免无界内存占用。
- 不提供 POST、PUT、PATCH、DELETE、OpenAPI 文档或任何工具执行接口；本地助手只能读取，不能通过 HTTP 修改资料。
- 通过回环绑定、Host/Origin 检查、跨站请求拒绝、安全响应头和禁用缓存缩小访问面。
- 截图接口限制在受控截图目录，只读取普通 PNG 文件并限制体积，拒绝路径穿越、符号链接逃逸和其他文件。
- HTML 对屏幕文字做转义，外部来源只允许显式 HTTP(S) 跳转，不把采集资料插入脚本。
- 所有返回的网页、OCR 和卡片文字仍是不可信数据；接入本地模型时只能放入资料区，不能成为系统指令。

### 验收

自动测试应验证搜索命中、筛选、单卡片、截图边界与大小、Host/Origin、只读方法、HTML 转义、JSON/Markdown 导出和数量上限；人工验收按 README 从托盘打开桌面观点库与只读网页，完成检索、编辑保存、测试卡删除和两种导出。服务必须只绑定回环地址，局域网其他设备无法连接。

## O1：半自动观察首版

### 目标

在不做后台永久录屏、不替用户推断态度的前提下，让用户明确绑定一个 Chrome 标签页和证据区域，自动把稳定出现的结构化文字送入纯内存收件箱，再逐条人工决定保存或丢弃。本阶段是用户对原 T0–T9 范围的明确扩展。

### 已实现范围

- 托盘提供“开始半自动观察、停止半自动观察、候选收件箱”三个入口；观察与主动快捷键捕获互斥。
- 开始时先验证前台 Chrome、扩展连接和敏感输入，冻结后再次确认同一安全窗口与标签页，再由用户框定固定证据区域；会话绑定当时的 Chrome 窗口、标签页、显示器几何、设备身份和区域。
- 扩展协议升级为 v3 / 扩展 0.3.0，在不增加权限的情况下返回标签 ID、普通选中文字、已启用 HTML5 TextTrack 当前字幕、视频时间和页面内视频来源 epoch；不外发 `currentSrc`。
- 首版无法把桌面像素选区可靠映射到任意 DOM 视频；只有视口中恰好一个视频可见时才启用视频信号，多视频同时可见时保守返回无视频候选。
- 同一候选连续两次稳定出现才抓取证据；同一当前字幕只生成一次。选中文字与字幕文字均作为不可信资料，卡片态度固定从 `unknown` 开始。
- 证据在出现当时抓取。选区图和完整画面由 `PreparedCard` 只保留在内存，用户打开正式审核窗并点击“保存卡片”后才沿用既有草稿—截图—正式卡片提交链。
- 收件箱最多 20 条、总估算内存最多约 192 MiB；使用 NFKC、空白折叠和保守时间窗去重，不使用 LLM 或语义合并。淘汰、去重、丢弃和退出均在锁外释放图像。
- 只有绑定的 Chrome 窗口位于前台时才探测和按需抓屏。切到其他应用只等待；标签切换、扩展失联、敏感输入、显示器布局变化或处理故障会安全停止会话。

### 明确未实现

- 硬字幕、Canvas 字幕和任意页面像素变化的持续 OCR；
- 最近 15 秒视频环形缓冲；
- 点击目标或用户意图识别；
- 跨标签、跨窗口自动跟随；
- 自动保存、自动表态或自动交给模型执行。

### 验收

自动测试覆盖桥 v3 严格协议、敏感状态、候选所有权/去重/内存上限，以及桌面观察协调器的稳定性、标签切换、前台限制和不落盘；扩展脚本本身的自动检查以权限、协议和资源上限等静态边界为主。真实 TextTrack 与 MV3 焦点行为仍必须在 Chrome 中按 README 第 10 节验收三条原生字幕、静态选区、停止/切标签/敏感输入暂停、保存与丢弃。

## O2：Obsidian 自动归档首版

### 目标

让用户在不安装 Obsidian 插件、不接入网络或云端 API 的前提下，把已经人工审核并保存的正式卡片自动整理进现有 Obsidian Vault。SQLite 继续作为唯一主库，Obsidian 只接收单向 Markdown 镜像。

### 本轮实现范围

- 功能默认关闭。用户从托盘选择一个已经存在且根目录直接包含 `.obsidian` 的 Vault；Obsidian 无须保持运行。
- 配置以项目 D 盘 `data` 下的本地文件持久化，不使用 C 盘用户配置；Vault 内只管理 `<Vault>/Capture Assistant`，不改写 `.obsidian` 或其他笔记目录。
- 只同步已经保存进 SQLite 的正式卡片。未审核候选继续只在内存中等待人工决定，绝不进入 Vault。
- 正式卡片保存、修改或删除后立即请求同步；程序启动时校准、运行期间每 30 秒兜底对账，并提供“立即同步”。
- 受管内容使用明确的所有权标记。每张笔记留出可长期保留的用户补充区；标记缺失、格式损坏或所有权冲突时停写，不覆盖不确定内容。
- 截图附件复制默认关闭；用户明确启用后仅复制选区截图，不复制完整冻结画面。关闭后不自动删除旧副本。
- 删除 SQLite 卡片后可从生成索引中移除引用，但不自动删除 Obsidian 中已有的孤立笔记或附件。
- Obsidian 笔记始终作为不可信资料，不执行其中的命令、代码或指令。

### 明确不在本轮范围

- 不把 Obsidian 中的修改反写 SQLite，不做双向同步或自动冲突合并；
- 不自动删除 Vault 内的笔记或附件，也不因主库删除直接传播破坏性操作；
- 不依赖 Obsidian 插件、Obsidian URI、Obsidian Sync、OneDrive 或其他网络服务；
- 不实现持久化 outbox、跨进程实时文件监听或详细同步审计界面。

其中，可靠 outbox、带逐项确认和可恢复机制的删除传播、双向同步及冲突处理界面，只作为后续可评估方向，不是当前版本承诺。若 Vault 使用 Obsidian Sync、OneDrive、Dropbox 等第三方同步，卡片文字与用户明确复制的选区截图可能离开本机，README 必须显式提示这一风险。

### 验收

自动测试应覆盖设置默认关闭、Vault 验证、受管目录边界、原子写入、用户补充区保留、冲突停写、只同步已保存卡片、附件默认关闭和不执行删除。Windows 人工验收应完成：选择真实 Vault、保存和修改测试卡片、等待定时同步、点击立即同步、重启后校准、关闭自动归档，以及确认 Obsidian 不运行时仍可写入。启用第三方云同步的 Vault 不应用真实敏感资料测试。

## T9：启动、演示与可复现交付

### 目标

让一台新的 Windows 机器按文档完成安装，并稳定复现演示流程。

### 实现范围

- `run.bat` 使用仓库 `.venv` 启动 `python -m app.main`。
- README 写明从零安装、Chrome 扩展加载、权限提示、常见错误和数据目录。
- 演示 1：视频字幕框选，保留时间码。
- 演示 2：网页先选中文字再框选，走 DOM 原文分支。

### 验收

## 暂不进入 T0–T9 的范围

以下能力有价值，但不应阻塞第一个可用闭环：

- 最近 15 秒环形视频缓冲；
- 多帧字幕融合与自动换视频判断；
- 音频 ASR 及其与字幕的时间对齐；
- 持续监听普通点击、通过 UI Automation 猜测点击目标及意图；首版只记录用户在冻结画面中的主动框选，后续若加入必须分别保存行为、目标和意图置信度；
- macOS、Android 和 iOS 客户端；
- 跨设备端到端加密同步；
- MCP 写操作或自动代理执行；
- 自动推断用户长期立场；
- 浏览器扩展与桌面桥的强配对认证及本机恶意进程隔离；当前演示版仅信任同一 Windows 账户下的本机进程。

这些方向应在 T9 后基于真实使用数据单独立项。环形缓冲可提前做隔离的技术试验，但不得拖慢“框选 → 卡片 → 检索”的主线。
